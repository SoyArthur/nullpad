# NULLPAD 🎮

**Mobile phone as virtual gamepad** — Wiimote / DualSense / Xbox / Joy-Con  
WebSocket over HTTPS · ViGEmBus XInput · IR via gyro · Haptics feedback

---

## Quick Start

### Requirements
- **Windows 10 / 11**  
- **Node.js 18+** — [nodejs.org](https://nodejs.org)  
- **ViGEmBus driver** — installed automatically by `install.bat`  
- **Visual Studio C++ Build Tools** — installed automatically by `install.bat` when `vigemclient` needs them  
- Phone and PC on the **same Wi-Fi network**

### Install (once)
```
Double-click install.bat
```
This will:
1. Verify Node.js (including fnm environments)
2. Install ViGEmBus driver if missing
3. Offer automatic installation of the Visual Studio C++ workload required by native `vigemclient`
4. `npm install` and compile the native ViGEm binding
5. Generate self-signed SSL certificate
6. Open firewall port 8443

### Run
```
Double-click start.bat
```
- The terminal prints the detected **PHONE / LAN URL** and any other detected LAN addresses  
- Scan the QR code with your phone  
- Accept the SSL warning (self-signed cert)  
- Pick your controller layout

## Dolphin Setup (Wiimote)

1. Open Dolphin → **Controllers**
2. Set Port 1 to **XInput** (not emulated Wiimote)
3. Map:
   - D-Pad → D-Pad buttons
   - Right Stick → IR pointer
   - LB → Shake
   - Face buttons → A/B/1/2

> Dolphin reads the right stick as IR when XInput emulation is used.

## Controller session lifecycle

NULLPAD exposes **one virtual Xbox 360 controller at a time**. Leaving a controller page explicitly closes its WebSocket and releases/resets the ViGEm target. If a phone refreshes, the browser restores a page from bfcache, or a previous socket becomes stale, the server cleans the old session before accepting the new one. A protocol-level ping/pong watchdog also removes dead connections automatically.

If Cemu shows a second controller after repeated development runs, close any older NULLPAD/server process still running and reopen `start.bat`; a single running NULLPAD instance can own only one target.

## Config

All tuneable values are in `config.js`:
- `PORT` — default `8443`
- `IR.BETA_RANGE / GAMMA_RANGE` — tilt sensitivity
- `IR.DEADZONE` — stick deadzone
- `IR.SMOOTHING` — gyro smoothing (0 = raw, 1 = frozen)
- `HAPTICS.POLL_MS` — rumble polling interval

## Troubleshooting

**Phone can't connect**  
→ Make sure the phone and PC are on the same local Wi-Fi/LAN (not guest Wi-Fi)  
→ Use the exact **PHONE / LAN URL** printed by `start.bat`; do not use a VirtualBox/VMware/WSL address  
→ `start.bat` automatically regenerates the certificate if the PC's LAN IP changed  
→ Check that Windows Firewall allows TCP 8443 on the local subnet  
→ If the page still cannot be reached, check the router for **AP/client isolation**; some guest Wi-Fi networks intentionally prevent wireless clients from talking to each other  
→ The first HTTPS visit may show a self-signed certificate warning; that is separate from network connectivity

**SSL warning on phone**  
→ Normal for self-signed certs. Tap "Advanced → Proceed"  
→ On iOS, may need to trust the cert in Settings → General → About → Certificate Trust

**Controller not detected in games**  
→ Verify ViGEmBus is installed: Device Manager → "Nefarius Virtual Gamepad Emulation Bus"  
→ Start NULLPAD before launching the game  
→ Some games require XInput — check game settings

**Gyro not working**  
→ iOS: tap anywhere on the Wiimote screen first (permission prompt)  
→ Android: grant motion sensor permission if prompted  
→ Check if browser supports DeviceOrientationEvent

## Free HUD Editor

Open the `✥` HUD button on any controller page. Every visible gameplay control is independently editable — not the whole controller as one object. Tap a control to select it, drag it anywhere on the viewport, use `−` / `+` to resize it, or pinch with two fingers directly on that control to resize it. `Reset` restores the current default layout and `Classic` removes the saved custom layout. Each controller profile/mode keeps its own layout in browser storage.

The editor uses normalized viewport coordinates, so layouts adapt when the phone size/orientation changes. While editing, gameplay input is blocked so dragging a button cannot accidentally press it. Desktop keyboard arrows nudge the selected control, with Shift for larger steps.

## Motion / Cemu DSU

NULLPAD keeps normal controller input on the ViGEm Xbox 360 target, while mobile motion data is exposed separately through the standard Cemuhook/DSU UDP protocol on `127.0.0.1:26760` by default.

On the Wiimote page, **⌁ Motion / DSU** opens the motion panel. It can: enable/disable the DSU motion channel, enable/disable the tilt-to-right-stick pointer proxy, change tilt sensitivity, choose which XInput action receives shake (`LB`, `RB`, `A`, `B`, `X`, `Y`, `L3`, `R3`, or none), calibrate the gyro, and test phone vibration. Settings are saved on the device.

In Cemu, use **GamePad Motion Source → DSU1** and point it at `127.0.0.1:26760`. The DSU protocol's standard actual-controller packet carries accelerometer and gyroscope fields, while its unofficial motor extension can carry rumble commands. ([Cemu Wiki](https://wiki.cemu.info/wiki/Motion_Controls), [Cemuhook protocol](https://github.com/v1993/cemuhook-protocol))

The phone browser cannot directly expose the Wii Remote's physical IR camera or its proprietary speaker protocol. NULLPAD therefore uses device orientation as a pointer proxy and provides rumble through the browser Vibration API where supported. `navigator.vibrate()` is limited across browsers and requires user activation in supporting implementations. ([MDN Vibration API](https://developer.mozilla.org/en-US/docs/Web/API/Vibration_API), [MDN Navigator.vibrate](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate))
